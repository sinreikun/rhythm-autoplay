# RhythmAutoplay

画面キャプチャだけを頼りに音ゲーを自動プレイする、汎用「外部」オートプレイプログラムです。
プロセスメモリや譜面ファイルは読みません。最初の対応タイトルは Steam 版 **HYPNOSYNC**（App ID 2986590）です。

設計の全体像は [docs/design.md](docs/design.md) を参照してください。

## 使い方（利用者向け）

1. 最新 Release から **`RhythmAutoplay.exe`（ランチャー）だけ** をダウンロードして、好きな場所に置きます。
2. あとはその exe を実行するだけです。起動のたびに GitHub の最新版を確認し、本体を自動で取得・更新してから起動します（導入先: `%LOCALAPPDATA%\RhythmAutoplay`）。本体を別途ダウンロードする必要はありません。
3. キー設定は HYPNOSYNC のデフォルトのままで大丈夫です（下の「HYPNOSYNC のキー配置」参照）。ゲーム内でキーを変更している場合は、`profiles/hypnosync.json` を自分の配置に合わせて書き換えてください。

### GUI（v0.3〜）

本体を引数なしで起動すると小さな GUI が開きます（ランチャー経由の通常起動もこちらです）。

- **プロファイル切替**: 対象ゲームをドロップダウンで選べます。`profiles` フォルダの JSON を編集・追加すると一覧に反映されます（同じ gameId は JSON 側が優先）。
- **オーバレイ表示**: ゲーム画面に認識範囲（レーン台形と判定ライン）を重ねて表示します。
- **範囲調整**: チェックを入れるとオーバレイのハンドルをドラッグして、レーンの幅・上端・中心・判定ラインの位置を変更できます。変更はプロファイルごとに自動保存されます。
- **タイミング調整**: スライダーと数値入力（上下ボタン付き）で発火オフセットを ms 単位で調整できます。
- **プレイ / DRY-RUN / 停止 / スナップショット** の各ボタンのほか、状態とログを表示します。
- ウィンドウの位置と設定は `%LOCALAPPDATA%\RhythmAutoplay\gui-settings.json` に保存され、次回起動時に復元されます。

### コンソールでの利用

```
RhythmAutoplayBody.exe play                    実プレイ開始（F9 で終了）
RhythmAutoplayBody.exe play --dry-run          入力せず、検出と発火予定だけ表示（較正用）
RhythmAutoplayBody.exe play --offset-ms -15    発火時刻の全体オフセットを指定
RhythmAutoplayBody.exe snapshot                較正用にフレームと検出結果を保存
```

前提: ゲームのウィンドウが画面上に見えていること（キャプチャは画面キャプチャ方式です）。

## HYPNOSYNC のキー配置

HYPNOSYNC は4レーンに5色のノーツが流れ、色ごとに対応キーが違う12キー設計です（赤/青はレーンごとに別キー、紫は同時押し、黄はどちらでも可、横長ノーツは方向キー）。本プログラムはゲームのデフォルト配置（EDIT KEYBINDS 画面で確認済み）をそのまま使います。

| レーン | 1 | 2 | 3 | 4 |
|---|---|---|---|---|
| 赤キー（下段 B1–B4） | F | G | H | J |
| 青キー（上段 T1–T4） | R | T | Y | U |

方向キー（レバー）: 上=W / 左=A / 下=S / 右=D

## 開発者向け

- 言語: C# (.NET 8)。ランチャーは Native AOT、本体は self-contained 単一ファイルで公開します。
- 版管理: リポジトリ直下の `version.txt` が唯一の正です。**改修のたびに版を上げて main へ push** すると、GitHub Actions がテスト→ビルド→Release 公開まで自動で行います（同じ版の Release がある場合は公開をスキップします）。
- 構成:
  - `src/RhythmAutoplay.Launcher` — 起動用 exe。最新版確認・本体の取得（SHA-256 照合つき）・起動だけを担います。
  - `src/RhythmAutoplay.App` — 本体。
  - `src/RhythmAutoplay.Core` — プロファイル、到達時刻の予測、入力スケジューラなどの共通コア。
  - `profiles/` — ゲーム別プロファイル（データ）。
  - `tests/` — コアの単体テスト。

## 現在の状態

- v0.1.x: 土台版。ランチャー＋自動更新、HYPNOSYNC プロファイル、予測/スケジューラのコアとテスト、CI による版付き Release 公開まで。
- v0.2.x: 実プレイ経路（キャプチャ→レーン検出→追跡/到達予測→SendInput）を実装。SendInput が HYPNOSYNC で通ることは実機で確認済み。到達予測は透視の加速を織り込んだ射影予測（v0.2.1）。検出の較正が継続課題です。
- v0.3.0: GUI を追加。オーバレイ表示とドラッグによる範囲・判定ライン調整、タイミング調整、プロファイル切替、設定とウィンドウ位置の保存に対応。
- v0.3.1: HYPNOSYNC 実機較正。青ノーツの実測色（シアン寄り h=0.537）に合わせて色範囲を拡張、レーン形状を実プレイ画面の実測値（上端 Y=0.563、消失点 Y≈0.39）に差し替え、白シェブロン矢印の検出を強化（隙間許容・明度しきい値）。GUI に「形状を初期値に戻す」ボタンを追加。
- v0.3.2: 誤入力対策。コンボ数字の半透明ゴースト（実測 v≈0.25 / s≈0.35）を色分類の床上げで除外し、画面下部に出現する UI（判定文字・数字）を発火させない「出現ゲート」を追跡器に追加。方向ノーツの基準位置を波模様下の横線（塊の最下行）に変更。
- v0.3.3: ヒット時のレーン発光（縦に長い run）をノーツと誤認しないよう、レーン検出に塊の高さ上限を追加。方向推定を作り替え: 字形がレーン端まで届くため外形では読めず、印ピクセルの重心軌跡（左右）とレーン中央部の印比率（上下）で判定する方式に変更し、実スクリーンショット4件（右・左・左・上）で検証。
- v0.3.4: 矢印は方向の票が入るまで予約を保留し、フレーム間の推定を多数決で決める（模様が流れるアニメーションで推定が揺れるため）。追跡の対応付けを予測位置ベース＋全体の貪欲割り当てに変更（同色連打の取り違え対策）。同キーが保持中に次の押下が来たら離してから押し直す。塊の高さ上限を 8.5% に緩和（同色2連の融合 run を落とさない）。発火処理をキャプチャ前に前倒し。
- v0.3.5: 出現ゲートを引き上げ（判定文字 BASED! が Y≈0.77 と想定より低い位置に出る実測に対応）。プレイの予約・発火を時刻つきで `%LOCALAPPDATA%\RhythmAutoplay\logs` に記録（タイミング較正用）。
- v0.3.6: 矢印ノーツと同時に来る通常ノーツ対策。白帯の上に半透明で重なった通常ノーツを、帯の内側だけ色相のみの緩い分類で拾い、白による色 run の分断を橋渡しする。矢印の方向推定の統計は白印だけで取り、重なった通常ノーツに歪められないようにした。
- v0.3.7: 高速譜面（TRANCE）でレーンノーツの予約がほぼ全滅した問題の対策。初検出位置のゲートを緩め（84%位置）、UI との見分けは「実際に下ったか」の動き確認に移した。塊の成立条件を広がり併用に戻し、薄いノーツを落とさないようにした。予約ホライズンを 1.2 秒に短縮。
